Rooflines, Arithmetic Intensity & the 240 Rule

A visual walk through the JAX Scaling Book roofline math — matmul costs, memory vs compute bound, the batch dimension, and distributed communication.

1 · What a matmul costs

The example op is X * Y → Z, all in bf16 (2 bytes per number):

Bytes loaded 2DF + 2BD

Read both inputs. Each element is bf16 = 2 bytes.

load Y: D×F × 2 = 2DF
load X: B×D × 2 = 2BD

FLOPs 2BDF

Z has B×F outputs; each is a length-D dot product.

each output = D MACs
1 MAC = 2 FLOPs (mul + add)
B×F × 2D = 2BDF
The trap: the two "2"s mean different things.
In 2DF, 2BD, 2BF → the 2 = bytes per element (bf16 = 2 bytes).
In 2BDF → the 2 = FLOPs per multiply-add (one multiply + one add). Totally unrelated coincidence.

2 · Arithmetic intensity

Intensity = how much compute you do per byte moved. It decides if you are compute-bound or memory-bound.

Intensity = FLOPs / bytes = 2BDF / (2BD + 2DF + 2BF) = BDF / (BD + DF + BF)

High intensity compute-bound

Lots of FLOPs per byte. Tensor cores stay busy. This is what you want.

Low intensity memory-bound

Few FLOPs per byte. Cores sit idle waiting on HBM. The ReLU/RMSNorm situation.

3 · The roofline

Plot achievable performance vs intensity. Two regions: the sloped memory wall and the flat compute ceiling. The corner is the crossover intensity.

4 · B, D, F — not all dimensions are equal

SymbolMeaningTypical sizeWho sets it
Bbatch size = number of tokens processed at once (rows of X, Z)1 → ~1000sYOU (runtime choice)
Dmodel hidden dimension> 8000fixed by model
Ffeed-forward / output dimension> 8000fixed by model

B is the only free variable. It is the row count of the activations, and it means tokens, not requests:

decode (1 token/step) → B ≈ number of concurrent requests (small)
prefill / training → B ≈ total tokens in the batch (large)
2 requests × 512 tokens = B of 1024 tokens, not B=2 sequences.

B is the weight-reuse factor

The weight matrix Y[D,F] must be loaded no matter what. B = how many tokens share that one load.

B = 1 memory-bound

Load the entire [D,F] weights → use them for one token. You just dragged weights across HBM to compute one row.

B = 1000 compute-bound

Load [D,F] once → reuse for 1000 tokens. Weights amortized, cores fed.

5 · Why intensity ≈ B, and the 240 rule

When B is small compared to D and F (true: B < 1024, D,F > 8000), the denominator collapses:

BDF / (BD + DF + BF) ≈ BDF / DF = B

So intensity ≈ B. You cross into compute-bound when intensity beats the hardware's FLOP-to-bandwidth ratio:

TPU: 1.97e14 FLOP/s ÷ 8.2e11 byte/s = 240
The rule: per-replica batch > 240 tokens → compute-bound. Below that → memory-bound. (GPUs: ~300, same idea.)

6 · "Per-replica" batch

Work is split across many chips (data parallelism). Each chip = a replica. The roofline is about one chip, so B means the per-replica token count.

7 · Distributed roofline — three times, two bandwidths

Across many chips you track three times, and the op is bounded by whichever dominates.

T_math compute

FLOPs / (N × chip FLOP/s)

Total work split across N chips.

T_mem memory

HBM bytes / HBM bandwidth

On-chip memory ↔ chip. FAST (TB/s).

T_comms communication

network bytes / NETWORK bandwidth

Chip ↔ chip over the interconnect. This is the one people get wrong.

Key: T_comms uses the NETWORK bandwidth, not HBM bandwidth. They are different pipes.
HBM (for T_mem)Network (for T_comms)
rolememory ↔ chipchip ↔ chip
TPU v5e~819 GB/sICI ~tens-hundreds GB/s
GPU H100~3.35 TB/sNVLink ~900 GB/s (in-node)
InfiniBand ~50-100 GB/s (cross-node)
speedfastslower (esp. cross-node)
op time ≈ max( T_math, T_mem, T_comms ) (if they overlap; else the sum)

You are comms-bound when you move too many bytes over the slow network relative to your FLOPs — the chips idle waiting on the interconnect, exactly like a memory-bound kernel waits on HBM. The comms bytes come from the parallelism strategy's collectives (data-parallel all-reduce, tensor-parallel all-gather, pipeline sends).

bytes matmul loads 2DF+2BD, writes 2BF  (2 = bf16 size)

FLOPs matmul does 2BDF  (2 = mul+add per MAC)

intensity = FLOPs/bytes = BDF/(BD+DF+BF) ≈ B

B = tokens (your choice) · D,F = model dims (fixed >8000)

B > 240 tokens per replica → compute-bound (GPU ~300)

T_mem uses HBM bandwidth · T_comms uses NETWORK bandwidth
